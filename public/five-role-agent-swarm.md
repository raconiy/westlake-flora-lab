# 五职责协作使用说明

## 同学怎么用

打开[西湖·生境的 GPT 输入框](https://raconiy.github.io/westlake-flora-lab/#assistant)直接提问。要提交改动，点「提建议」，写上物种、年龄或季节、看到的现象和期望结果。例如「银杏，18 年，秋季。树干下半段出现一圈横向叶片，拖动树龄后仍然存在」。在建议板上查看服务接收情况、主控处理进度和后续交付。

## 主控怎么派工

| 职责 | 任务字段 role | 一项实际工作 |
| --- | --- | --- |
| 植物生长与形态 | botany | 修复跨物种的枝叶出生、附着与脱落 |
| 根土与力学 | physics | 核对受风时根颈接地，测量枝条受力后的位移 |
| 校园布局与渲染 | scene | 按照片放置乔木和路灯，核对相机视角 |
| 助手与基础设施 | infra | 修复队列重试、网关连接及结果留存 |
| 测试与验收 | qa | 复验前序改动、检查回归，记录发布版本 |

在运行此版协调器的服务器上，将下面的 JSON 提交给本机协调器。已配置协调器认证时附上对应的 Bearer 凭据。

```sh
curl --fail-with-body http://127.0.0.1:8788/api/suggestions \
  -H 'Content-Type: application/json' \
  -d '{"role":"physics","requestKey":"wind-root-01","title":"风载下的根颈接地","kind":"code","prompt":"验证幼树和成树在风载下的根颈间隙；若有漂浮，修复并增加回归测试。"}'
```

记录返回的任务 ID。连接中断后重发相同内容时沿用原 requestKey，可以取回同一个任务。验收人员需要复核时提交 role 为 qa 的新任务，在 handoffFrom 数组填入已完成任务的 ID。交接包含原任务校验结果、摘要、是否合并和已留存的输出哈希。发布由主控在代码复核、测试和部署成功后确认。

## 怎么看账号用量

职责和账号是两个字段。职责决定谁领取任务，GPT‑Load 选择具体请求的上游账号。在网关的请求日志中按时间、请求 ID 和上游凭据核对实际成功次数与输出 token。页面的账号健康数表示可用容量。需要核查服务器、网关或访问分组时，见[服务器操作手册](./server-gptload-operations.md)。
